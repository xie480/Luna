# Execution Memory Ledger 技术设计文档（多任务编排防遗忘专项）

## 1. 文档目标

本文档定义 Luna 在 OpenClaw 多任务编排中的“执行记忆账本（Execution Memory Ledger）”方案，解决以下问题：

1. 防止任务链执行过程中遗忘用户原始命令  
2. 防止阶段推进过程中偏离批准蓝图  
3. 为下一阶段提供结构化、可消费的关键结果  
4. 支撑失败恢复、局部重规划、审计追踪与前端回放  

---

## 2. 问题定义

在 Plan/Phase/Node 的长链路执行里，常见风险包括：

- 上下文漂移：模型逐步偏离原始意图
- 事实丢失：阶段输出未被稳定传递到下一阶段
- 恢复困难：审批中断/服务重启后无法快速恢复现场
- 难以审计：只能看零散日志，缺少完整任务事实链

结论：仅有普通日志不足以支撑“编排级短期记忆”。

---

## 3. 设计原则

1. **真实与可用分离**：事件层保真，快照层提炼  
2. **不可变优先**：用户原始命令只写一次，不可覆盖  
3. **阶段可消费**：输出必须结构化，能直接喂给下一阶段  
4. **最小侵入**：兼容现有 `PLAN_*`、SSE、审计链路  
5. **可恢复**：中断后能重建运行上下文并继续执行  

---

## 4. 总体架构（双层模型）

## 4.1 事件事实层（Event Ledger）

- 形态：append-only 事件流（不更新历史）  
- 作用：保留所有执行事实，用于审计、回放、调试  
- 特性：强追踪（traceId/planId/phaseId/nodeId），高完整性

## 4.2 工作快照层（Working Snapshot）

- 形态：每阶段完成后更新一次“最新快照”  
- 作用：给下一阶段模型输入提供短小、结构化上下文  
- 特性：高可读、低 token、可快速恢复
