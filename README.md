**Luna 定义**
一个主打陪伴、具备高度自主性与多模态交互能力的本地化 AI 桌面智能体（Desktop AI Agent）。

具体来说，Luna 具备以下几个核心维度的特征：

1 深度陪伴与绝对的人格稳定性                                                                                                                                                                            
• 人格约束：通过代码中的 PromptTemplates.SYSTEM_PROMPT（LUNA 核心人格宪章 v3.0）进行严格的系统级约束，确保其行为和性格不崩坏。                                                                       
• 情绪化表达：结合 EmotionEnum（愤怒、害羞、微笑等）与后期的 Live2D 及 TTS 语音集成，Luna 能够以生动的表情和语音与用户进行情感交流。                                                                 
• 多层记忆体系：拥有短期上下文（Redis）、中期数据库和长期文件记忆，甚至在开关机时会进行记忆的预热与总结，确保跨日对话的连贯性。                                                                      
2 高度的自主性与主动感知                                                                                                                                                                                
• 主动交互：打破了传统的“一问一答”模式。Luna 能够感知桌面状态（如用户打开了某个软件）、结合历史会话进行自我反思，并在适当时机主动向用户输出建议或发起对话。                                          
• 自我进化：在满足特定策略时，Luna 能够主动将新知识、联网搜索结果或反思结论写入本地向量知识库，甚至动态调整自己的提示词。                                                                            
3 强大的本地化与知识管理能力                                                                                                                                                                            
• 多模型驱动：后端架构支持灵活接入 Ollama（本地）、Qwen、Gemini 等多种大语言模型。                                                                                                                   
• 个人知识库（RAG）：能够扫描、解析本地磁盘文件（PDF/Office/图片等）并进行向量化索引，结合联网搜索能力，为用户提供精准的检索增强回答。                                                               
4 深度的系统级集成（MCP）                                                                                                                                                                               
• 通过模型上下文协议（MCP），Luna 不仅能“说”，还能“做”。她被设计为常驻桌面的应用，能够受控地调用工具、读取文件、甚至打开和操作桌面软件。                                                             
5 企业级的工程架构                                                                                                                                                                                      
• 作为一个完整的后端系统，Luna 包含了完善的生命周期管理、Token 认证（AuthService）、结构化日志审计、定时备份恢复以及系统监控告警，确保了长期运行的稳定性。

总结：Luna 不是一个简单的聊天套壳工具，而是一个有记忆、有情绪、能看（感知桌面/扫描文件）、能听能说（语音/Live2D）、能动手（MCP工具调用），并且会主动关心用户的全能型虚拟桌面伴侣。

**阶段设计**：

● 阶段1：准备和环境配置
○ 目标：明确需求、给Luna一个定义、提供架构设计
○ 检验方式：环境配置成功，基本应用可以成功运行

● 阶段2：本地对话
○ 目标：部署模型，提供HTTP接口并实现前端对话交互
○ 检验方式： 通过 API 发起 20 轮对话不崩溃；前端能正确渲染回复并显示延迟统计  

● 阶段3：会话短期记忆
○ 目标：实现会话管理，每次请求都能把最近N轮注入模型并保持整体主题连贯
○ 检验方式： 人工评估 10 轮对话中能引用最少 2 条早期消息  

● 阶段4：滚动摘要和上下文管理
○ 目标：定期浓缩早期对话，在上下文超限时进行替代
○ 检验方式：当历史长度超过阈值时，系统自动生成摘要并把旧轮次替换为摘要；人工评估摘要正确率 ≥ 80%

● 阶段5：本地向量知识库
○ 目标：建立文档分片、embedding、向量DB，实现检索增强回答。
○ 检验方式： 给定知识库文档，检索到 top-k snippet 并将其注入prompt

● 阶段6： 多层记忆体系  
○ 目标：实现短期内存、中期DB和长期文件三层记忆体系，提供写入与读取策略
○ 检验方式： 能依据查询检索出长期偏好并在会话中正确运用；持久化记录可恢复并通过完整性校验。

● 阶段7：基础MCP
○ 目标：实现简单 MCP，注册工具，模型只能通过注册接口调用工具
○ 检验方式： 模型请求调用工具 → MCP 执行 → 返回结果给模型，执行链路日志可审计且无越权调用。

● 阶段8：联网搜索能力
○ 目标： 集成受控联网搜索模块，MCP 可按需触发搜索并把结果结构化写入知识库或提示词  
○ 检验方式： 对外网查询返回结构化结果；MCP 执行时限、速率与权限控制有效；搜索结果被写入 KB 并能被检索到。

● 阶段9：提示词实时管理
○ 目标：实现提示词可被动态更新、推送并立即生效
○ 检验方式：通过管理接口更新 prompt → 下一次请求即生效；变更有版本记录与回滚接口

● 阶段9.5： 生命周期管理  
○ 目标： 开机时自动加载重要记忆/摘要并做预热；关机时总结本次会话并持久化到长期存储  
○ 检验方式： 开机日志显示已加载 N 条 summary；关机后产生会话总结文件并在下次开机被读取与引用  

● 阶段10：主动更新知识库与提示词
○ 目标： Luna在满足策略时（新信息、搜索结果、反思结论）能主动将新条目写入 KB 或调整提示词；写入受策略/权限限制。
○ 检验方式： 触发场景（如新搜索结果或模型反思建议写入）→ MCP 审核/自动写入 → KB 可检索到新条目且变更有审计记录。

● 阶段11：运行时主动MCP
○ 目标：Luna能在运行时基于输入和自我反思主动触发MCP
○ 检验方式：模拟场景（如三天未提锻炼）→ 系统自动发起建议/搜索并写入记忆；行为遵循频率阈值和用户偏好，且日志记录完整

● 阶段12：日志记录和审计
○ 目标：实现结构化日志 （对话、工具调用、搜索、KB 写入、错误/异常）与审计链，支持查询与溯源
○ 检验方式： 日志存储可查询（时间/会话/事件类型）；能导出某次会话完整审计链并验证一致性；日志保留策略生效  

● 阶段13：定时备份与恢复
○ 目标： 实现知识库、记忆、提示词、关键配置的定时备份与可恢复方案  
○ 检验方式： 执行定时备份任务 → 产生备份文件→ 模拟恢复流程并验证数据一致性

● 阶段14：监控和告警
○ 目标： 部署运行时监控（服务可用性、内存/CPU、模型 OOM、请求错误率、延迟）并配置告警策略
○ 检验方式： 人为触发异常（如人工降低模型内存阈值或制造 500）→ 监控探测到并发送告警；告警包含必要上下文（日志链接，错误快照）  

● 阶段15： 人格稳定与一致性  
○ 目标： 通过持久化 persona、prompt 版本控制与一致性约束，使开关机与跨日对话在人格/情绪/语态上一致  
○ 检验方式： 跨日对话样本自动化评估（相似度/风格一致性）≥ 0.8；人工盲测一致性达标  

● 阶段16：桌面嵌入
○ 目标： 把 Luna 嵌入桌面（托盘常驻、窗口、前端交互），后端以服务化方式暴露本地 HTTP/IPC  
○ 检验方式： 安装包在目标机器上能安装并启动服务；UI 能唤起/隐藏，模型与 UI 交互正常；系统托盘可控制开关  

● 阶段17： 磁盘文件扫描与索引  
○ 目标： 实现受控的文件扫描（白名单目录、授权机制）、解析（PDF/Office/TXT/OCR）、分片并向量化索引入 KB  
○ 检验方式： 扫描 N 个不同类型文件（含 PDF/图片）→ 对应 chunk 被索引并能被检索到；变更检测/增量索引有效  

● 阶段18： 桌面状态感知  
○ 目标： 实现桌面事件采集（窗口标题、程序启动、文件活动），建立事件 pipeline 送入后端处理。  
○ 检验方式： 在本机打开/关闭指定程序 → 事件被采集并在系统日志/队列中可见 → Agent 能读取并响应

● 阶段19： 基于桌面事件的主动输出  
○ 目标： Luna 根据桌面/程序/文件变化主动输出建议（低频、可控），并能记录用户反馈用于调整触发策略  
○ 检验方式： 配置触发规则 → 执行触发动作（例如打开 IDE）→ Luna 提示被显示并在 1 次内得到用户反馈；系统记录反馈并更新触发计数

● 阶段20：语音输入
○ 目标：可以通过麦克风等外设向Luna对话
○ 检验方式：多次对话识别成功且文本正确率高  

● 阶段21： Live2D 集成  
○ 目标： 接入 Live2D SDK，使 emotion → 表情/帧动画映射，并支持切换/微动作/翻转动画。  
○ 检验方式： 根据情绪触发不同立绘文件并播放对应动画；切换无撕裂、帧率满足 UI 要求  

● 阶段22： AI 语音（TTS/ASR）集成  
○ 目标： 接入 TTS（本地或云）并可选接入 ASR，实现语音输入/输出，支持情绪化语音合成与中断机制  
○ 检验方式： TTS 能把对话文本合成语音且播放成功；ASR 的准确率在目标语域下满足阈值（自定义）；语音中断/停止功能可用  

● 阶段23： 桌面部署与最终验收  
○ 目标： 把所有组件打包为可安装版本（或自启动服务），包含权限/隐私设置；通过长期稳定性测试  
○ 检验方式： 72 小时持续运行测试（自动化脚本），无关键故障，MTTR（平均修复时间）在预期范围内；备份/恢复演练通过

1. 定期扫描知识库
2. 能够结合历史会话进行反思
3. 可以联网搜索
4. 可以将新知识结构化存入知识库
5. 主动向用户输出内容
6. 常驻
7. 能够感知桌面状态
8. 能读文件、扫描磁盘
9. 能有长期记忆
10. 主打陪伴式存在
11. 可以打开桌面软件，进行观测以及操作
